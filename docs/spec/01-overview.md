## 한 줄 소개
국내외 기술 블로그 글을 자동으로 모아 한곳에서 검색하고, 읽은 기록과 관심 태그에 맞춰 글을 추천하는 개발자용 리더

## 문제 정의
- 기술 블로그가 기업·개인으로 흩어져 있어 매번 여러 사이트를 돌아야 함
- RSS 리더는 모아주기만 하고, 과거 글을 한글로 검색하거나 "나한테 맞는 글"을 고르기 어려움
- 관심 없는 글이 섞여 피드가 금방 소음이 됨

## 페르소나

### P1. 주니어 백엔드 개발자 "지훈" (2년 차)
- 출퇴근 시간에 기술 글을 읽으며 공부함
- 니즈: 내 스택(Spring, MySQL, Kafka)과 관련된 실무 글을 빠르게 찾고 싶음
- 불만: 회사 블로그 10여 곳을 즐겨찾기로 돌아다님, 예전에 본 글을 다시 찾기 어려움

### P2. 시니어 프론트엔드 개발자 "수민" (7년 차)
- 팀 기술 세미나 주제를 고르기 위해 트렌드를 살핌
- 니즈: 이번 주에 많이 다뤄진 키워드, 특정 주제(예: "React Server Components")의 국내 사례 모아보기
- 불만: 검색 엔진 결과에 광고·저품질 글이 섞임

### P3. 운영자(본인)
- 수집 소스를 관리하고 수집 실패·데이터 품질을 확인함
- 니즈: 어떤 소스가 실패하는지, 수집량이 정상인지 한눈에 확인

## 핵심 가치
1. **모아보기**: 검증된 기술 블로그 소스만 수집해 소음 없는 피드 제공
2. **찾기**: 한글 형태에 강한 전문 검색과 출처·태그·기간 필터
3. **골라주기**: 관심 태그와 읽은 기록을 바탕으로 한 개인화 추천
4. **원문 존중**: 본문 전체를 복제하지 않고 요약과 원문 링크로 트래픽을 원작자에게 돌려줌

## 서비스 원칙 (제약)
- 본문 전체 저장·노출 금지. 제목, 메타 설명 또는 본문 앞부분 기반 요약(최대 300자), 썸네일 URL, 원문 링크만 저장
- 수집은 공개 RSS/Atom 피드만 사용. 크롤링으로 페이지 본문을 긁지 않음
- 로그인 없이 피드·검색 사용 가능. 북마크·읽은 기록·추천은 로그인 필요

## 포트폴리오 어필 포인트 (기술 목표)
| 영역 | 목표 | 증명 방법 |
|---|---|---|
| 수집 파이프라인 | 소스별 주기 수집, 재시도, 실패 격리, 중복 0건 | 수집 로그 대시보드, 테스트 |
| 검색 | 앱 bigram 토큰 + InnoDB FULLTEXT 기반 한글 부분 검색 (MariaDB ngram 파서 부재 대응), 글 10만 건에서 p95 300ms 이하 | `LIKE` 기준선 대비 부하 측정 리포트(전/후 비교) |
| 추천 | 태그 가중치 → TF-IDF 유사도 순 단계적 고도화 | 추천 클릭률 비교 지표 |
| 성능 | 커서 기반 페이지네이션, 인덱스 근거 문서화 | EXPLAIN 결과, 측정 수치 |

## 범위 요약
- MVP: 소스 관리, 주기 수집, 피드, 검색, 회원, 북마크, 읽은 기록, 관심 태그, 태그 기반 추천, 수집 현황 관리자 화면
- Next: TF-IDF 유사 글/추천 고도화, 주간 급상승 키워드, 소스 제안, 이메일 다이제스트, 소셜 로그인
- 상세: `02-features.md`

## 용어
- 소스(Source): 수집 대상 블로그 1곳 (RSS/Atom URL 1개)
- 글(Post): 소스에서 수집한 개별 게시물
- 태그(Tag): 글에 자동 부여되는 기술 키워드 (사전 기반)
- 수집 실행(Crawl Run): 소스 1곳에 대한 1회 수집 작업과 그 결과
