## 수집

### F-001 소스 등록·수정·비활성화 (MVP)
- 사용자 스토리: 관리자로서 수집할 블로그를 등록하고 관리해, 검증된 소스만 피드에 노출하고 싶음
- 수용 기준
  - 소스 항목: 이름, 블로그 URL, 피드 URL(RSS/Atom), 유형(기업/개인), 로고 URL(선택), 수집 주기(분, 기본 60, 30~1440)
  - 피드 URL 등록 시 즉시 1회 가져와 유효한 RSS/Atom인지 검증하고, 실패하면 등록 거부와 사유 표시
  - 같은 피드 URL은 중복 등록 불가
  - 비활성화한 소스는 수집 대상에서 빠지고, 기존 글은 피드에 남음
  - 삭제 대신 비활성화만 제공
- 초기 데이터: 국내 기술 블로그 소스 30곳 이상을 시드로 제공

### F-002 주기 수집 (MVP)
- 사용자 스토리: 운영자로서 새 글이 자동으로 들어오길 원함
- 수용 기준
  - 활성 소스마다 설정 주기에 따라 수집 실행
  - 동시에 같은 소스를 두 번 수집하지 않음 (중복 실행 방지)
  - 소스 한 곳의 실패(타임아웃, 파싱 오류, 4xx/5xx)가 다른 소스 수집에 영향을 주지 않음
  - 요청 타임아웃 10초, 실패 시 지수 백오프로 최대 3회 재시도
  - 연속 5회 실패한 소스는 "오류" 상태로 표시하고 수집 간격을 `min(주기 × 2^(연속실패-4), 24시간)`으로 늘림 
  - 오류 상태 소스도 늘어난 간격으로 계속 수집하고, 한 번 성공하면 자동으로 정상 상태·실패 횟수 0으로 복귀함. 관리자는 수동 재개로 즉시 정상 상태로 돌릴 수 있음
  - 수집 실행마다 시작·종료 시각, 결과(성공/실패), 신규 글 수, 오류 메시지 기록
  - 조건부 요청(ETag/Last-Modified)을 지원해 변경 없는 피드는 다시 파싱하지 않음
  - 관리자는 특정 소스를 즉시 수집 실행할 수 있음. 이미 수집 중이면 거부
  - 변경 없음(304) 응답은 성공으로 간주하고 연속 실패 횟수를 초기화함

### F-003 중복 제거 (MVP)
- 사용자 스토리: 독자로서 같은 글이 피드에 두 번 보이지 않길 원함
- 수용 기준
  - 원문 URL을 정규화(쿼리의 utm_* 등 추적 파라미터 제거, 끝 슬래시 통일)해 같은 글로 판단
  - 같은 소스 내 guid가 같으면 같은 글로 판단
  - 이미 있는 글이 다시 수집되면 제목·요약 변경분만 갱신하고 새 글로 만들지 않음
  - 동시 수집 상황에서도 중복 저장 0건

### F-004 요약 생성 (MVP)
- 사용자 스토리: 독자로서 원문을 열기 전에 글 내용을 짐작하고 싶음
- 수용 기준
  - 피드의 description/summary/content에서 HTML 태그를 제거한 텍스트로 요약 생성
  - 최대 300자, 문장 중간에서 잘리면 말줄임표 추가
  - 본문 전체 텍스트는 저장하지 않음 (검색·태깅용 처리 후 폐기)
  - 썸네일: 피드의 이미지 정보가 있으면 URL만 저장, 없으면 비움

### F-005 자동 태깅 (MVP)
- 사용자 스토리: 독자로서 글을 기술 주제별로 분류해 보고 싶음
- 수용 기준
  - 관리자가 관리하는 태그 사전(태그명 + 동의어 목록, 예: `Kubernetes` ← k8s, 쿠버네티스) 기반으로 제목·요약·피드 카테고리에서 태그를 추출
  - 피드 카테고리는 재태깅에도 쓰기 위해 글 메타데이터로 보관함 (본문 아님)
  - 글마다 최대 5개 태그, 제목에 나온 태그를 우선
  - 초기 태그 사전 100개 이상 시드 제공
  - 태그 삭제는 MVP 범위 아님 (추가·수정만)
  - 태그 사전이 바뀌면 기존 글 재태깅을 관리자가 실행할 수 있음 (Next 자동화)

### F-006 수집 현황 조회 (MVP)
- 사용자 스토리: 운영자로서 어떤 소스가 실패하고 있는지, 수집량이 정상인지 한눈에 보고 싶음
- 수용 기준
  - 소스 목록: 상태(정상/오류/비활성), 마지막 성공 시각, 최근 7일 신규 글 수, 연속 실패 횟수
  - 소스 상세: 최근 수집 실행 50건 이력과 오류 메시지. 결과는 성공 / 성공(변경 없음) / 실패로 표시
  - 전체 요약: 오늘 수집된 글 수, 실패 중인 소스 수
  - 수집 실행 이력은 90일 보관 후 삭제

## 피드

### F-010 최신 피드 (MVP)
- 사용자 스토리: 독자로서 새로 올라온 기술 글을 최신순으로 훑고 싶음
- 수용 기준
  - 글 카드: 제목, 소스 이름·로고, 발행일, 요약, 태그, 썸네일, 북마크 여부(회원)
  - 발행일 내림차순, 무한 스크롤 (페이지당 20건)
  - 커서 기반 페이지네이션. 스크롤 중 새 글이 들어와도 중복·누락 없음
  - 발행일이 미래이거나 없는 글은 저장 시점에 수집 시각으로 대체해 저장함 (조회 시 계산하지 않음)
  - 회원에게는 읽은 글을 흐리게 표시

### F-011 피드 필터 (MVP)
- 사용자 스토리: 독자로서 관심 있는 출처나 주제만 보고 싶음
- 수용 기준
  - 필터: 태그(복수 최대 10개, OR), 소스(복수 최대 20개), 소스 유형(기업/개인)
  - 비활성 소스도 소스 필터에서 선택 가능 (기존 글이 피드에 남으므로)
  - 필터 상태는 URL 쿼리에 반영돼 공유·새로고침 시 유지

### F-012 원문 이동 및 조회수 집계 (MVP)
- 사용자 스토리: 독자로서 카드를 누르면 원문으로 이동하고 싶음
- 수용 기준
  - 카드 클릭 시 새 탭으로 원문 열기
  - 클릭은 서비스를 거쳐 기록됨 (조회수 +1, 회원이면 읽은 기록 저장)
  - 같은 사용자(회원 ID 또는 비회원 식별자)의 같은 글 클릭은 24시간 내 1회만 조회수 반영
  - 기록 실패가 원문 이동을 막지 않음

### F-013 인기 글 (MVP)
- 사용자 스토리: 독자로서 요즘 많이 읽히는 글을 보고 싶음
- 수용 기준
  - 기간 선택: 24시간 / 7일 / 30일 (현재 시각 기준 롤링 윈도우)
  - 해당 기간 발행 글 중 조회수 1 이상인 글의 상위 20건 (조회수 0인 글은 제외, 동점은 최신 발행순)
  - 해당 글이 없으면 "이 기간에 읽힌 글이 아직 없음" 빈 화면과 최신 피드 이동 링크 표시
  - 실시간일 필요 없음. 최대 10분 지연 허용

### F-014 글 카드 배지 (MVP, 020)
- 사용자 스토리: 독자로서 피드에서 새 글과 요즘 많이 읽히는 글을 바로 알아보고 싶음
- 수용 기준
  - `NEW`: 발행 24시간 이내 글
  - `인기`: 최근 7일 인기 글 상위 20건(F-013 기준)에 드는 글. 최대 10분 지연 허용
  - 한 카드 최대 2개(`NEW` → `인기` 순), 소스 줄 시간 오른쪽 작은 텍스트 배지, 아이콘·애니메이션 없음
  - 적용: S-01·S-02·S-04·S-08 글 카드. S-03은 `NEW`만, S-09 컴팩트 카드는 미표시

### F-015 상단 탭 확대·6탭 구성 (M7, 021)
- 사용자 스토리: 독자로서 보고 싶은 글 묶음으로 한 번에 이동하고 싶음
- 수용 기준
  - (031에서 F-017로 대체) 1단 탭: 최신 / 추천(로그인 시에만) / 인기 / 보안 뉴스 (023: 기업·개인 탭 삭제, 게스트 추천 탭 숨김)
  - 글자 14px, 탭 36px(줄 52px), 활성 탭은 책갈피형(위·좌·우 테두리, 하단 선 없이 아래 영역과 이어짐) + 굵은 글자 (사용자 피드백, 021). 360px은 가로 스크롤
  - 탭마다 URL 경로, 새로고침·공유 시 같은 탭

### F-017 기술 뉴스·보안 뉴스 2탭 + 내부 탭 (M11, 031)
- 사용자 스토리: 독자로서 기술 소식과 보안 소식을 크게 나눠 보고, 그 안에서 최신·추천·인기를 골라 보고 싶음
- 수용 기준
  - 1단 탭: 기술 뉴스 / 보안 뉴스. hero 제목은 1단 탭 이름
  - (033) 1단 탭 순서 자유 게시판 / 기술 뉴스 / 보안 뉴스. 데스크톱은 1단 탭 hover 펼침 메뉴 + 목록 우측 상단 정렬 선택, 모바일은 토글 그룹 유지
  - 기술 뉴스 내부 탭 `[최신 | 추천 | 인기]`: `/tech`, `/tech/for-you`, `/tech/popular`. 분야 탭은 최신·인기에서만
  - 보안 뉴스 내부 탭 `[최신 | 인기]`: `/security`, `/security/popular`. 지역 `[전체 | 국내 | 해외]` 공통
  - 비회원도 추천 내부 탭이 보이고, 누르면 로그인 유도 모달 (직접 진입은 로그인 화면)
  - 옛 주소 `/`·`/for-you`·`/popular`·`/company`·`/personal`은 새 주소로 넘기고 쿼리 유지
  - 1단 탭 이동 시 해당 탭의 최신. 기술 내부 탭 이동 시 분야 유지·태그·소스 초기화, 보안 내부 탭 이동 시 지역·출처 유지

### F-016 기업·개인 블로그 탭, 분야 탭 (M7, 021)
- 사용자 스토리: 독자로서 기업 블로그만, 또는 백엔드 글만 모아 보고 싶음
- 수용 기준
  - (023 삭제) 기업/개인 탭 → 사이드바 소스 유형으로 대체, `/company`·`/personal`은 `/?sourceType=`로 이동
  - 2단 분야 탭(최신·인기): 전체 / BE / FE / AI / Data / Infra / Mobile / Security (023 영어 표기). 분야별 포함 분류는 discussion 021 표
  - 분야와 사이드바 필터는 AND, URL 쿼리 동기화
  - 글 10만 건 분야 피드 p95 300ms 이하

- 기술 용어 표기(023): 업계에서 영어가 더 흔한 기술 용어(분야·태그 분류·태그 이름)는 영어. 한글 이름은 동의어로 남겨 검색·자동 태깅 유지

## 검색

### F-020 키워드 검색 (MVP)
- 사용자 스토리: 독자로서 "카프카 컨슈머 리밸런싱" 같은 주제의 과거 글을 찾고 싶음
- 수용 기준
  - 검색 대상: 제목, 요약, 태그, 소스 이름
