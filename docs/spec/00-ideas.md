- 작성: pm

- 선정 기준: 1인 구현 가능, 데모 가능한 화면, 면접에서 설명할 기술 포인트가 분명할 것

## A. 드롭 — 한정판 선착순 판매·티켓팅 대기열 플랫폼

- 한 줄 소개: 수량 한정 상품/좌석을 오픈 시각에 수천 명이 동시에 사도 초과 판매 없이 공정하게 처리하는 판매 플랫폼
- 타깃 사용자: 소규모 굿즈 판매자, 소규모 공연·행사 주최자 / 구매자
- 핵심 기능
  - 판매 이벤트 생성(오픈 시각, 수량, 1인 구매 한도)
  - 가상 대기열: 입장 순번·예상 대기 시간 실시간 표시
  - 좌석/재고 임시 선점(N분 홀드) → 결제(모의) → 확정, 미결제 시 자동 반환
  - 관리자 대시보드: 실시간 판매량, 대기열 길이, 이탈률
- 포트폴리오 어필 포인트
  - 동시성 제어: 비관적 락 vs 낙관적 락 vs 원자적 UPDATE 비교 실험과 수치
  - 대기열 설계, 홀드 만료 처리(스케줄러), 멱등 결제 요청
  - k6 부하 테스트 결과(TPS, p99, 초과 판매 0건)를 README에 그래프로 제시
- 난이도: 상
- 예상 기술 리스크
  - 대기열을 MariaDB만으로 구현하면 병목 가능. Redis 추가 여부 결정 필요
  - 부하 테스트 환경을 로컬에서 의미 있게 재현하기 어려움
  - 흔한 주제라 "구현 깊이"로 차별화해야 함

## B. 비드라이브 — 실시간 경매 플랫폼

- 한 줄 소개: 입찰이 실시간으로 반영되고, 마감 직전 스나이핑을 막는 공정한 온라인 경매
- 타깃 사용자: 중고·수집품 판매자 / 입찰자
- 핵심 기능
  - 경매 등록(시작가, 최소 호가 단위, 마감 시각)
  - WebSocket 실시간 입찰가·입찰 로그·남은 시간 동기화
  - 소프트 클로징: 마감 N초 전 입찰 시 마감 자동 연장
  - 자동 입찰(최대 금액 위임), 낙찰/유찰 처리, 알림
- 포트폴리오 어필 포인트
  - 동시 입찰 정합성(같은 금액 동시 입찰, 순서 보장)
  - 서버 권위 시간과 클라이언트 시계 보정
  - 입찰 이벤트를 append-only 로그로 저장 → 감사 추적·재현 가능
  - 자동 입찰 간 경쟁 해소 알고리즘
- 난이도: 상
- 예상 기술 리스크
  - 다중 서버 인스턴스 시 WebSocket 브로드캐스트에 pub/sub 필요
  - 마감 처리 타이머 정확도와 서버 재시작 시 복구
  - 시연용 동시 사용자 확보 어려움 → 봇 입찰 시뮬레이터 필요

## C. 데브피드 — 기술 블로그 통합 피드 + 검색·추천

- 한 줄 소개: 국내 기업·개인 기술 블로그 글을 수집해 검색하고, 읽은 기록 기반으로 글을 추천하는 개발자용 리더
- 타깃 사용자: 기술 트렌드를 따라가고 싶은 주니어~시니어 개발자
- 핵심 기능
  - RSS/Atom 주기 수집, 중복 제거, 본문 요약 추출
  - 한글 전문 검색(태그·기간·출처 필터, 하이라이트)
  - 읽음·북마크·관심 태그 기반 개인화 추천
  - 트렌드: 주간 급상승 키워드
- 포트폴리오 어필 포인트
  - 수집 파이프라인(스케줄러, 재시도, 실패 격리)
  - MariaDB FULLTEXT(ngram) 튜닝과 검색 품질 개선 과정
  - 추천: 태그 가중치 → TF-IDF 유사도 → (확장) 임베딩 순으로 단계적 고도화
  - 수십만 건 데이터에서 쿼리 성능 개선 전후 비교
- 난이도: 중
- 예상 기술 리스크
  - 외부 블로그 저작권: 본문 전체 저장 대신 요약+원문 링크로 제한 필요
  - MariaDB ngram 파서 품질 한계 → 별도 검색엔진 도입 유혹
  - 추천 품질을 정량 평가하기 어려움

## D. 업타임랩 — API 모니터링 + 공개 상태 페이지

- 한 줄 소개: 등록한 URL/API를 주기적으로 체크해 장애를 감지·알림하고, 공개 status page와 장애 타임라인을 제공하는 서비스
- 타깃 사용자: 개인 개발자, 사이드 프로젝트 운영자, 소규모 팀
- 핵심 기능
  - 모니터 등록(HTTP 메서드, 기대 상태코드, 응답 키워드, 주기)
  - 장애 감지(연속 N회 실패 판정), 복구 감지, 이메일/웹훅 알림
  - 응답 시간 차트, 가동률(24h/7d/90d)
  - 공개 상태 페이지 + 인시던트 타임라인 작성
- 포트폴리오 어필 포인트
  - 대량 모니터 스케줄링(작업 분산, 지연 없는 주기 실행)
  - 시계열 데이터 적재·다운샘플링·보존 정책(파티셔닝)
  - 오탐 방지 로직, 알림 중복 억제
  - 실제로 자기 서비스를 이 서비스로 모니터링하는 "도그푸딩" 스토리
- 난이도: 중
- 예상 기술 리스크
  - 체크 결과 데이터가 빠르게 쌓여 저장 공간·쿼리 성능 관리 필요
  - 단일 지역 체크라 네트워크 일시 장애 오탐 가능
  - 기능 자체가 기존 SaaS와 유사 → 설계 깊이로 어필해야 함

## E. 퀴즈아레나 — 실시간 멀티플레이 퀴즈 대결

- 한 줄 소개: 방을 만들고 링크로 초대해 수십 명이 동시에 퀴즈를 풀고 실시간 순위가 바뀌는 대결형 서비스
- 타깃 사용자: 스터디 모임, 강사·발표자, 사내 행사 진행자
- 핵심 기능
  - 퀴즈 세트 제작(객관식/주관식, 제한 시간)
  - 방 생성·참가 코드, 진행자 화면 / 참가자 화면 분리
  - 서버 기준 타이머, 응답 속도 반영 점수, 실시간 리더보드
  - 결과 리포트(문항별 정답률, 오답 분포)
- 포트폴리오 어필 포인트
  - WebSocket 방(room) 상태 관리, 재접속 시 상태 복원
  - 네트워크 지연 보정(서버 수신 시각 기준 공정 판정)
  - 문항 진행 상태 머신 설계
  - 직접 시연하기 쉬움(면접관이 폰으로 바로 참가 가능)
- 난이도: 중
- 예상 기술 리스크
  - 방 상태를 메모리에 두면 서버 재시작·스케일아웃 시 유실
  - 동시 응답 집중 시 리더보드 갱신 비용
  - 기획이 단순해 보일 수 있음 → 실시간 처리 품질로 차별화 필요
