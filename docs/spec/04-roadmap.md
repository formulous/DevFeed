## 역할별 착수 순서 (M0)
1. `dba`: `01~03` 기준 ERD·DDL 초안 → `server` 검토
   - 우선 검토 요청 사항: 글 중복 판단 키, 검색용 FULLTEXT 인덱스, 조회수·읽은 기록의 쓰기 부하와 보관 정책
2. `server`: 스키마 기반 `docs/api/openapi.yaml` 작성 → `client`·`pm` 검토
   - 우선 검토 요청 사항: 수집 스케줄러 구조, 커서 페이지네이션 규격, 인증 토큰 방식
3. `client`: 화면 골격·라우팅·onyx-ui 컴포넌트 매핑 착수, API 확정 전 mock 사용

## 리스크와 대응
| 리스크 | 영향 | 대응 |
|---|---|---|
| MariaDB ngram 파서 부재(확인됨), 한글 검색 품질·성능 한계 | M3 목표 미달 | 앱 bigram 토큰 + InnoDB FULLTEXT로 구현(discussion 002, schema D-03). M3 측정 미달 시에만 Mroonga·외부 검색엔진 재검토 |
| 외부 블로그 피드 형식 제각각 | 파싱 실패 증가 | 소스별 실패 격리, 시드 소스 사전 검증, 파서 테스트 케이스 축적 |
| 저작권 | 서비스 신뢰도 | 요약 300자 이하·원문 링크 필수 원칙 고수 |
| 조회·읽은 기록 쓰기 폭증 | DB 부하 | 24시간 중복 제외, 집계 테이블 분리 여부를 dba와 협의 |
| 실사용자 부족으로 추천 평가 어려움 | 어필 약화 | 가상 사용자 행동 시드 생성기로 오프라인 평가 지표 산출 |
