# 017. 좌측 필터 카드 재설계: 스크롤 없는 칩 + 선택 창

- 상태: decided
- 제기: pm (사용자 요청)
- 관련: client
- 관련 문서: `docs/spec/03-screens.md` S-01·S-04·필터 선택 창(S-12), `docs/spec/02-features.md` F-011·F-021, `docs/discussions/016`

## 배경
- 016에서 사이드바를 독립 스크롤로 바꿨지만, 사용자 피드백: "더보기"를 누르면 스크롤바가 지저분함
- pm 확인 (2026-11-20, 공개 페이지 1280×800 캡처)
  - 태그 153개를 체크박스 줄 목록으로 펼침(`더보기 (143)`), 소스 36개는 처음부터 전부 줄 목록 → 사이드바가 화면보다 훨씬 김
  - 사이드바 스크롤 + 섹션 내부 스크롤이 겹쳐 스크롤바가 2개 생기는 구조. 카드 하단도 화면에서 잘려 보임
- 원인은 스크롤 모양이 아니라 **수백 개 선택지를 좁은 사이드바에 줄 목록으로 다 펼치는 구조**임

## 결정 (pm)
- 사이드바는 **스크롤 없이 한 화면에 들어오는 요약 패널**로 바꾸고, 전체 목록은 **선택 창(모달)** 에서 고름

### 사이드바 (데스크톱 `lg` 이상)
```
┌ 필터 ────────────────────────┐
│ 태그                    전체 › │
│ [Java 202] [JavaScript 167]   │  ← 인기 태그 12개 칩 (줄바꿈 배치)
│ [테스트] [React] [Rust] ...    │     선택된 칩은 채움색 + ✓
│                               │
│ 소스 유형                      │
│ [ 전체 | 기업 | 개인 ]          │  ← 세그먼트 버튼
│                               │
│ 소스                    전체 › │
│ [토스 ✕] [카카오 ✕]             │  ← 선택된 소스만 칩 (없으면 안내 문구)
│ 글 많은 소스 5개 칩             │     "많이 쓰는 소스" 빠른 선택
│                               │
│ 선택 3개 · 초기화               │
└───────────────────────────────┘
```
- 태그: 글 수 상위 12개 칩 + 선택된 태그(상위 12개 밖이어도) 앞쪽에 표시. "전체 ›"로 선택 창 열기
- 소스 유형: 라디오 3개 → 세그먼트 버튼 1줄
- 소스: 선택된 소스 칩 + 글 많은 소스 5개 빠른 선택 칩. "전체 ›"로 선택 창 열기
- 사이드바 높이: 1280×720에서 스크롤 없이 들어와야 함. 독립 스크롤(016)은 낮은 화면을 위한 안전장치로만 남기고, 스크롤바는 얇게(`scrollbar-width: thin`, 트랙 투명, 평소 흐리게) 처리
- 섹션 내부 스크롤(016의 "약 12줄 후 섹션 내부 스크롤")은 **폐지** → 스크롤바가 겹치는 일 없음

### 선택 창 (S-12, 새 화면 요소)
```
┌ 태그 선택 ─────────────────────────── ✕ ┐
│ [태그 검색.......................]       │
│ 분류: 전체 | 백엔드 | 프론트엔드 | 데이터 | 인프라 | AI | ...
│ ┌───────────────────────────────────┐ │
│ │ [Java 202] [Spring 73] [Kafka 41]  │ │  ← 칩 그리드, 창 안에서만 스크롤
│ │ [JPA 30] [Redis 28] ...            │ │
│ └───────────────────────────────────┘ │
│ 선택 2/10                 [초기화] [적용] │
└───────────────────────────────────────┘
```
- 태그: 검색 + 분류 탭(태그 사전 `category`, 16개, 없으면 "기타") + 칩 그리드. 최대 10개 (F-011)
- 소스: 같은 창 형식. 검색 + 유형 탭(전체/기업/개인) + 로고·이름 칩. 최대 20개 (F-011)
- [적용]을 눌러야 필터 반영 (창 안에서 여러 개 고르는 동안 피드가 매번 다시 로드되지 않게)
- 데스크톱은 가운데 모달(최대 폭 640px, 최대 높이 80vh), 모바일은 하단 시트(전체 높이)
- 키보드: Esc 닫기, 포커스 가두기, 칩은 `aria-pressed`

### 모바일 (`lg` 미만)
- 기존 필터 드로어 대신 피드 상단 한 줄: `[태그 ▾] [유형 ▾] [소스 ▾]` 버튼 → 각각 위 선택 창(하단 시트)
- 선택된 필터는 기존 칩 줄(`[Kafka ✕] [기업 ✕] 초기화`)에 표시

### 적용 화면
- S-01 홈, S-04 검색 (같은 필터 컴포넌트)
- S-08 북마크의 태그 필터도 같은 선택 창 재사용 (가능하면)

## 수용 기준
- 1280×720, 1440×900에서 사이드바에 스크롤바가 생기지 않음 (태그·소스 아무것도 안 고른 상태, 태그 10개·소스 20개 고른 상태 모두)
- 스크롤바가 생기는 곳은 선택 창의 칩 목록 하나뿐
- 상위 12개 밖 태그도 선택 창에서 검색·분류로 3번 이내 동작으로 선택 가능
- 필터 상태는 지금처럼 URL 쿼리와 동기화 (F-011)
- 360px 모바일에서 필터 버튼 줄과 하단 시트 동작
- Playwright 캡처: 사이드바(기본·최대 선택), 태그 선택 창, 소스 선택 창, 모바일 시트

## API·데이터
- 변경 없음. 인기 태그는 `GET /tags?sort=POST_COUNT&size=12`, 전체 태그는 `GET /tags`, 소스는 `GET /sources` (글 수 정렬이 필요하면 client가 정렬, 없으면 server에 `postCount` 추가 요청)
