# 035. 정렬을 글자 탭으로, 댓글순·좋아요순 추가

- 상태: open
- 제기: pm (사용자 요청)
- 관련: client, server, dba
- 관련 문서: `docs/discussions/033` 정렬 선택, `docs/spec/03-screens.md` 공통 레이아웃·S-16, `docs/spec/02-features.md` F-013·F-072·F-094

## 배경
- 사용자 요청 (2026-11-23): 우측 상단 `[최신순 ▾]` 펼침 선택(033)을, 분야 탭(`전체 · BE · FE …`)처럼 **글자 탭**으로 펼쳐 두고 기준을 늘림
- 사용자 결정
  - 기준: 자유 게시판 `최신순 · 인기순 · 댓글순 · 좋아요순` / 기술 뉴스 `최신순 · 추천순 · 인기순 · 댓글순` / 보안 뉴스 `최신순 · 인기순`
  - 댓글순·좋아요순 기간: 인기순처럼 `24시간 | 7일 | 30일` 선택

## 결정 (pm)
### 화면 (client)
```
전체 · 질문 · 토론 · 공유                 최신순 · 인기순 · 댓글순 · 좋아요순   [✎ 글쓰기]
                                        (인기·댓글·좋아요순이면 아래 [24시간 | 7일 | 30일])
```
- 목록 맨 위 줄: 왼쪽 분야·말머리 글자 탭, **오른쪽 정렬 글자 탭** (분야 탭과 같은 크기·스타일, 선택 = 기본 글자색). 033의 `[최신순 ▾]` 선택 메뉴 제거
- 1단 탭 hover 펼침 메뉴(033)에도 같은 항목 추가 (자유 게시판 4개, 기술 뉴스 4개, 보안 뉴스 2개)
- 모바일·터치: 지금 토글 그룹에 같은 항목 (자유 게시판 4칸·기술 뉴스 4칸). 360px에서 넘치면 가로 스크롤 규칙(1단 탭과 같음)
- 기간 선택은 인기·댓글·좋아요순 사이 이동 시 유지 (기본 7일)
- 비회원 추천순 → 로그인 안내 (031 그대로)
- 주소(제안, 최종은 client·server 합의)
| 화면 | 주소 |
|---|---|
| 자유 게시판 댓글순·좋아요순 | `/community/comments?period=`, `/community/likes?period=` |
| 기술 뉴스 댓글순 | `/tech/comments?period=&field=` |
- 목록: 인기순과 같은 **순위형 상위 20건** (순위 번호 + 해당 수치 표시: 댓글순은 `💬 N`, 좋아요순은 `♡ N` 강조)

### 기준 (server)
- 그 기간에 **발행된** 글 중 댓글 수(`comment_count`) 또는 좋아요 수(`like_count`) 1 이상, 내림차순 상위 20건. 동점은 최신 발행순, 최대 10분 지연(캐시) 허용
  - 자유 게시판: 보이는 글(`VISIBLE`)만, 말머리 필터 적용
  - 기술 뉴스: 블로그 글만(보안·자유 게시판 제외), 분야(`field`) 필터 적용
- 기존 인기 API에 정렬 파라미터를 더할지 새 경로를 둘지는 server 재량. `openapi.yaml` 갱신
- dba: 카운터 정렬 쿼리가 기존 인덱스(기간 범위 스캔 후 정렬)로 충분한지 검토. 새 인덱스·마이그레이션이 필요하면 운영 적용 전 사용자 승인

## 수용 기준
- 세 1단 탭 우측 상단 정렬 글자 탭과 hover 메뉴·모바일 토글이 같은 항목, 선택 상태 일치, 펼침 선택 메뉴 없음
- 댓글순·좋아요순: 기간 전환 동작, 0건 글 제외, 기술 뉴스 댓글순에 보안·자유 게시판 글 없음
- 새 목록 p95 300ms 이하, 360px 가로 넘침 0, 라이트·다크 정상
- 기존 테스트·빌드 통과

## 의견

### client (검토·API 형태 제안, 2026-11-23)
- 화면 결정 모두 수용. 주소는 pm 제안 그대로 `/community/comments`·`/community/likes`·`/tech/comments` (`?period=`, 말머리·분야 유지). 기본 7일이면 `period` 생략(인기와 같음)
- 기간 유지: 인기·댓글·좋아요순 사이 이동 시 `period`를 함께 넘김. 최신·추천으로 가면 버림
- 데스크톱 맨 위 줄: 왼쪽 분야·말머리 글자 탭, 오른쪽 정렬 글자 탭, 자유 게시판은 그 오른쪽 `글쓰기`. 1024~1200px에서 기술 뉴스 분야 탭(전체+9개)과 정렬 4개가 한 줄에 안 들어가면 분야 탭만 가로 스크롤(정렬 탭은 줄이지 않음)
- 목록: 인기와 같은 순위형, 카드 메타를 `조회 N` 대신 `댓글 N`·`좋아요 N`로 바꾸고 강조
- API 형태 제안 (server 재량, 화면은 아래 형태로 mock 먼저 진행)
  - 기존 인기 경로에 `sort` 추가, 응답은 지금 `{ items: PopularPost[] }` 그대로 (`likeCount`·`commentCount`는 이미 PostSummary에 있음)
    - `GET /posts/popular?period&field&sort=VIEWS|COMMENTS` (생략 = VIEWS, 지금 동작)
    - `GET /community/popular?period&category&sort=SCORE|COMMENTS|LIKES` (생략 = SCORE, 지금 동작)
  - 다른 이름·새 경로로 정하면 명세 갱신 후 알려 주면 맞춤

### dba (1차) — 댓글순·좋아요순 쿼리 인덱스 검토: 새 마이그레이션 불필요
- 쿼리 형태는 인기순과 같음 (기간 범위 스캔 → 카운터 정렬 → 상위 20). 카운터는 `posts.comment_count`·`like_count` 비정규화 컬럼(026)이라 조인·집계 없음
  - 기술 뉴스: `WHERE kind = 'BLOG' AND published_at >= ? AND comment_count > 0 ORDER BY comment_count DESC, published_at DESC, id DESC LIMIT 20` → `idx_posts_kind_published`. 분야는 인기순과 같이 `EXISTS (post_tags PK)`
  - 자유 게시판: `community_posts`의 `(status[, category], published_at, post_id)` 인덱스로 기간 범위 → `posts` PK 조인으로 카운터 읽기
- 측정 (`devfeed_perf` 블로그 10만·커뮤니티 2만, DB p95)
  | 쿼리 | 7일 | 30일 | 30일 + 필터 |
  |---|---|---|---|
  | 기술 댓글순 | 0.62ms | 3.63ms | 분야 BACKEND 3.55ms |
  | 자유 댓글순 | 0.22ms | 0.77ms | 말머리 0.31ms |
  | 자유 좋아요순 | 0.23ms | 0.78ms | 말머리 0.29ms |
  - 기준 300ms 대비 여유 큼 → **인덱스·마이그레이션 없음**, 운영 적용 절차 불필요
- 주의: 카운터 정렬 키가 인덱스에 없어 기간 안 글 수에 비례함 (기술 댓글순 1년 범위면 5.5만 행 40ms). 기간은 24시간·7일·30일로만 열어 두기 바람 (`ALL`·1년 추가 시 재검토). 10분 캐시 전제
- `comment_count`는 `VISIBLE` 댓글+답글 수(026)라 삭제·숨김 댓글은 정렬에 반영 안 됨 → 화면 `💬 N`과 같은 값

### pm (client 검토 수용, 2026-11-23)
- 주소·기간 유지(인기·댓글·좋아요순 사이만)·좁은 폭에서 분야 탭만 가로 스크롤·카드 수치 강조 모두 수용
- API 형태(기존 인기 경로 + `sort`)는 pm 의견으로 타당함. 최종은 server가 정해 명세 반영

### pm (dba 검토 수용, 2026-11-23)
- 기존 인덱스로 충분(30일 최대 3.63ms), 마이그레이션 없음 → 운영 승인 절차 불필요. 기간은 24시간·7일·30일만 유지 (전체 기간 추가 시 재검토 조건 수용)

### server (2026-11-23) client 제안 형태 그대로 명세·구현·배포 완료
- 경로는 새로 만들지 않고 기존 인기 API에 `sort` 추가. 응답 `{ items: PopularPost[] }` 그대로 (`commentCount`·`likeCount` 포함)
  - `GET /posts/popular?period&field&sort=VIEWS|COMMENTS` (생략 = `VIEWS`, 기존 동작)
  - `GET /community/popular?period&category&sort=SCORE|COMMENTS|LIKES` (생략 = `SCORE`, 기존 동작)
  - 그 밖의 값은 400 (`/posts/popular?sort=LIKES` 포함). 보안 뉴스 인기는 변경 없음
- 기준: 기간 안 발행 글 중 해당 수 1 이상, 내림차순 상위 20, 동점 최신 발행순·id순. 기술은 블로그 글만·분야 필터, 자유 게시판은 `VISIBLE`만·말머리 필터. 캐시는 기간 × 필터 × 정렬별 10분
- `isPopular` 배지 집합은 sort와 무관 (조회수 WEEK 그대로)
- dba 쿼리 형태와 같음 (인덱스·마이그레이션 없음 확인 감사)
- 명세 `openapi.yaml` 갱신 (lint 기존 8 errors 그대로), 커밋 `65535b6`
- 검증: unit 173, e2e 84 통과 (035 e2e 2건 추가: 0건 제외·정렬·동점·필터·400·보안 뉴스 제외)
- 운영 배포 후: 세 정렬 200, 잘못된 sort 400. 서버 내부 응답 30일 기준 3~13ms. 자유 게시판 7일 댓글순 20건 댓글 수 30, 24, 18 … 내림차순 확인
- client: mock 형태 그대로 실서버 대조 부탁

### pm (server 배포 확인, 2026-11-23)
- 공개 API: `/community/popular?sort=COMMENTS|LIKES` 20건 내림차순, `category=QUESTION` 필터 동작, `/posts/popular?sort=COMMENTS` 블로그 글만(8건), 기술 `sort=LIKES`는 400(기획대로 기술 뉴스는 좋아요순 없음)
- 자유 게시판 댓글순·좋아요순 상위가 같은 글 순서인 건 시연 데이터 좋아요를 댓글 수에 비례해 넣었기 때문 (기능 문제 아님)
- 남은 것: client 배포 → pm 공개 확인
