# 008. 인기 글에 조회수 0인 글 포함 여부

- 상태: decided
- 제기: client
- 관련: pm, server
- 관련 문서: `docs/spec/02-features.md` F-013, `docs/api/openapi.yaml` `/posts/popular`

## 배경
- M2 실서버 연동 확인 (11-19) 중 `GET /posts/popular` 결과
  - `DAY`: 0건, `WEEK`: 13건 `[3, 0, 0, ...]`, `MONTH`: 20건 `[3, 0, 0, ...]`
- 기간 내 글을 조회수 내림차순으로 자르기 때문에 조회수 0인 글이 대부분을 채움. 화면에는 "조회 0"인 글이 2위부터 나열됨
- 지금은 실사용자가 없어서 두드러지지만, 출시 후에도 24시간 탭은 조회수 0인 글이 섞일 가능성이 큼

## 제안 / 한계점
- 제안 A (client 선호): `viewCount >= 1`인 글만 포함. 없으면 빈 배열 → client는 "이 기간에 읽힌 글이 아직 없음" 빈 화면 표시 (이미 구현)
- 제안 B: 현행 유지 (0인 글도 발행일 순으로 채움). client는 조회수 0이면 조회수 표시를 숨김
- 서버 쪽 변경은 조건 1개 추가 수준으로 예상함. 캐시(10분)에는 영향 없음

## 의견

### client (1차)
- A 제안. "인기 글"인데 조회 0이 순위에 오르면 신뢰가 떨어짐. 시드 데이터 검증 시점에는 빈 화면이 나와도 의미가 정확함
- client 쪽 변경은 A·B 모두 거의 없음

### server (1차)
- A 찬성. 서버 변경은 `AND view_count > 0` 조건 1개
  - 쿼리 계획 영향 없음: 지금도 `idx_posts_published` 범위(기간 내 글) 스캔 후 정렬이고, 조건은 그 범위 안에서 거르기만 함. 10분 캐시 유지
- 참고: 위 `DAY` 0건은 조회수 문제가 아니라 최근 24시간에 발행된 글이 없어서임 (시드 블로그들의 최신 글이 하루 이상 지남). A를 적용하면 출시 후에도 24시간 탭이 빈 화면일 때가 더 잦아짐 → client 빈 화면 문구로 충분하다고 봄
- 명세 변경 필요: `openapi.yaml` `/posts/popular` 설명에 "조회수 1 이상인 글만, 최대 20건(0건 가능)" 추가. pm 결정 후 server가 명세 먼저 고치고 구현함

## 결정 (pm)
- 결정 (2026-11-19): 제안 A. 인기 글은 기간 내 조회수 1 이상인 글만 포함, 동점은 최신 발행순. 없으면 빈 배열
- 근거: "인기"라는 의미와 맞지 않는 조회 0 글이 순위에 오르면 신뢰가 떨어짐. 서버 조건 1개 추가로 비용 작음
- 보완: 빈 화면은 막다른 화면이 되지 않게 최신 피드(S-01) 이동 링크를 함께 표시. 시연 시에는 조회 기록이 쌓인 상태로 보여줌
- 후속 작업:
  - pm - `02-features.md` v1.4 F-013 반영 (완료)
  - server - `/posts/popular`에 `view_count >= 1` 조건 추가, `openapi.yaml` description 보강
  - client - 빈 화면에 최신 피드 링크 추가
