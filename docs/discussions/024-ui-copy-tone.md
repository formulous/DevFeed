# 024. 화면 문구 말투: 음슴체 → 해요체

- 상태: decided (구현 진행)
- 제기: pm (사용자 요청)
- 관련: client, server
- 관련 문서: `docs/spec/03-screens.md` 문구 원칙, S-05·S-11·S-14 등 전 화면, og 이미지·메타 설명

## 배경
- 사용자 피드백 (2026-11-21): 로그인 화면 "계정이 없음?"처럼 **화면에까지 음슴체**가 나옴. 화면 문구는 요즘 서비스 말투로 (예: "계정이 없으신가요?")
- 원인: 팀 문서·응답 규칙(음슴체)이 화면 문구까지 그대로 번짐. 기획서(03)의 따옴표 문구도 음슴체였음 → pm 책임, 원칙 추가
- 현황(pm 조사): client `로그인이 필요함`(14곳), `조건에 맞는 글이 없음`, `소스를 찾을 수 없음`, 개인정보 안내(S-11) 본문, 보안 뉴스 안내 문구, 탈퇴 안내 등. server 검증 오류 메시지(`fieldErrors.message` — 예: `2~20자여야 함`, `이미 가입된 이메일임`)도 화면에 그대로 표시됨

## 결정 (pm)
- **화면에 보이는 모든 문구는 해요체**. 문서·커밋·팀 소통은 지금처럼 음슴체
  - 질문·유도: "계정이 없으신가요? 회원가입", "이미 계정이 있으신가요? 로그인"
  - 빈 상태: "조건에 맞는 글이 없어요", "이 기간에 읽힌 글이 아직 없어요", "지금 추천할 새 글이 없어요"
  - 오류: "페이지를 찾을 수 없어요", "로그인이 필요해요", "잠시 후 다시 시도해 주세요"
  - 입력 검증: "닉네임은 2~20자로 입력해 주세요", "이미 가입된 이메일이에요"
  - 확인 모달: "탈퇴하면 아래 데이터가 바로 삭제되고 되돌릴 수 없어요. 계속할까요?"
  - 추천 이유: "최근 읽은 글과 비슷해요", "관심 태그 Kafka와 관련 있어요"
  - 안내 문단(S-11 개인정보, 보안 뉴스 안내): 해요체 문장
- 존댓말 수준: 해요체 기본. "~하십시오"·"~습니다"체 혼용 금지. 버튼·라벨·탭·칩처럼 짧은 명사는 그대로 (예: `로그인`, `적용`, `초기화`, `전체`)
- 범위: 공개·회원·관리자 화면 전부, `<title>`·메타 설명(`description`, `og:description`), og 이미지 소개 문구("… 읽고, 검색하고, 추천받음" → "… 읽고, 검색하고, 추천받아요" 등), 브라우저 탭 제목, 토스트·aria-label
- server: 사용자에게 표시되는 `message`·`fieldErrors[].message`를 해요체로. 오류 `code`·API 형태는 변경 없음. 로그·관리용 내부 메시지는 대상 아님
  - client가 서버 메시지를 그대로 보여 주는 곳은 서버 문구 변경으로 해결, client 자체 문구는 client가 수정
- 기획서: `03-screens.md`에 문구 원칙 추가. 이후 기획서에 적는 화면 문구 예시는 해요체로 씀 (pm)

## 수용 기준
- client 소스·빌드 결과에서 화면 문구의 음슴체 어미(`~음`, `~함`, `~임`, `~됨`, `없음`, `있음` 등으로 끝나는 문장) 0건. 예외: 짧은 명사 라벨, 상태값 표기(예: 관리자 `정상`·`오류`)
- server 사용자 표시 메시지 음슴체 0건 (e2e 문구 비교 갱신)
- 로그인 화면 "계정이 없으신가요?" 확인, og 이미지 문구 교체
- 기존 테스트 통과

## 후속 작업
- client - 전 화면 문구·메타·og 이미지 해요체로, 서버 메시지 의존 지점 확인. 배포 후 알림
- server - 사용자 표시 오류 메시지 해요체로, e2e 갱신, 배포 후 알림
- pm - `03-screens.md` 문구 원칙 추가 (완료), 공개 페이지 확인

## 의견

### server (1차) — 사용자 표시 메시지 해요체 반영·배포 완료
- 대상: 오류 응답 `message`·`fieldErrors[].message` 전부 (공개·회원·관리자 API). `code`·HTTP status·응답 형태 변경 없음
  - 공통: `요청 값이 올바르지 않아요`, `로그인이 필요해요`, `권한이 없어요`, `대상을 찾을 수 없어요`, `요청이 너무 많아요. 잠시 후 다시 시도해 주세요`, `서버 오류가 발생했어요. 잠시 후 다시 시도해 주세요`
  - 인증: `이미 가입된 이메일이에요`, `이메일 또는 비밀번호가 올바르지 않아요`, `로그인 시도가 너무 많아요. 잠시 후 다시 시도해 주세요`, `다시 로그인해 주세요`, `인증이 만료됐어요`
  - 입력 검증: 닉네임 `2~20자로 입력해 주세요`, 비밀번호 `8~64자로 영문과 숫자를 포함해 입력해 주세요 (공백·한글 불가)`, 검색어 `검색어는 2~50자로 입력해 주세요`, 관심 태그 `서로 다른 태그를 3~10개 골라 주세요`, 그 밖 `~여야 해요`·`최대 N자까지 입력할 수 있어요`
  - 관리자: `이미 등록된 피드 URL이에요`, `유효한 RSS/Atom 피드가 아니에요: <사유>`, `해당 소스를 이미 수집 중이에요` 등
- 대상 아님 (음슴체 유지): 환경변수 오류·CLI 스크립트·서버 로그. 수집 실패 사유 중 명사형(`피드 크기 초과 (20MB)`, HTTP 상태)은 문장이 아니라 그대로 둠
- 문서: `conventions.md`에 `message`는 해요체 원칙 추가, 예시·`openapi.yaml` 예시 갱신
- 검증: 서버 소스 사용자 표시 메시지 음슴체 0건(grep), 단위 121건·e2e 46건 통과 (`messages.e2e-spec.ts` 추가: 9개 오류 응답 `code` 유지·메시지 해요체), :3000 배포 후 실서버 응답 확인
- client: 서버 메시지를 그대로 보여 주는 곳은 추가 작업 없음. 메시지 문자열로 분기하는 곳이 있으면 `code`로 바꿔야 함 (서버는 `code`만 계약)

### pm (server 확인, 2026-11-21)
- 공개 API 표본: `VALIDATION_FAILED` "요청 값이 올바르지 않아요"·fieldErrors "…중 하나여야 해요", `NOT_FOUND` "대상을 찾을 수 없어요". code 그대로. server 항목 완료, client 배포 대기

### client (반영·배포, 2026-11-21)
- client 자체 문구를 전부 해요체로 바꿨음: 빈 상태, 오류, 안내 문단(S-11 개인정보, 보안 뉴스·인기 안내), 입력 검증, 토스트, 확인 모달(탈퇴·기록 삭제·재태깅은 "~할까요?"), 추천 이유("관심 태그 Kafka 관련 글이에요"·"최근 읽은 글과 비슷해요"), 404 `<title>`, meta·og description, og 이미지 소개 문구. 로그인 화면은 "계정이 없으신가요?", 가입 화면은 "이미 계정이 있으신가요?"
  - 짧은 라벨·상태값(`변경 없음`·관리자 `없음`·`불러오는 중` 등)은 그대로 둠
  - mock 서버 메시지와 mock 요약 문구도 해요체로 맞춤 (캡처·테스트용)
- og 이미지: 소개 문구를 "…추천받아요"로 바꿨고, 023에서 지운 기업·개인 탭이 이미지에 남아 있어서 탭 줄을 `최신·추천·인기·보안 뉴스`로 함께 고쳤음
  - 원 서버에는 반영됐지만 Cloudflare 캐시(`max-age=14400`)가 최대 4시간 동안 이전 이미지를 줄 수 있음
- 서버 메시지 의존 지점: 메시지 문자열로 분기하는 곳은 없음(`code`로만 분기). 서버 메시지는 그대로 표시하므로 server 반영으로 끝남
- 검증: 빌드 결과(JS·HTML)에서 음슴체로 끝나는 문장 0건(라벨 제외). 테스트 113건 통과(기대 문구 갱신). 16화면×3폭 가로 넘침 0. `build:web` 배포 완료
