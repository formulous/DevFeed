# 038. 페이지별 검색 (기술 뉴스·보안 뉴스·자유 게시판)

- 상태: open
- 제기: pm (사용자 요청)
- 관련: dba, server, client
- 관련 문서: `docs/spec/02-features.md` F-020~F-022·F-024, `docs/spec/03-screens.md` S-04, schema D-03(bigram FULLTEXT)

## 배경
- 사용자 요청 (2026-11-23): 검색창이 모든 페이지에서 "기술 글 검색…"으로 기술 블로그만 찾음. 지금 보고 있는 페이지에 맞게 검색되게 개선
- 현재: 검색 색인(`post_search`)은 수집 시점에 블로그 글만 채움. 보안 뉴스 검색은 021에서 Next, 자유 게시판 글은 032에서 검색 제외(Next)

## 결정 (pm)
### 검색 범위 (scope)
| 페이지 | 검색창 안내 문구 | 범위 `scope` | 검색 대상 |
|---|---|---|---|
| 기술 뉴스 (`/tech/…`) | "기술 뉴스 검색…" | `tech` | 지금과 같음 (제목·요약·태그·소스 이름) |
| 보안 뉴스 (`/security/…`) | "보안 뉴스 검색…" | `security` | 제목·요약(최대 150자)·출처 이름 |
| 자유 게시판 (`/community/…`) | "자유 게시판 검색…" | `community` | 제목·본문(마크다운 제거 텍스트)·태그. 보이는 글(`VISIBLE`)만 |
| 그 외 화면(내 정보·검색 결과 직접 진입 등) | 마지막 범위, 없으면 기술 뉴스 | | |
- 결과 화면 주소: `/search?q=&scope=tech|security|community` (없으면 `tech`, 기존 링크 호환)
- 결과 화면 맨 위에 범위 글자 탭 `기술 뉴스 · 보안 뉴스 · 자유 게시판` — 같은 검색어로 다른 범위로 바로 전환, 각 범위 건수는 표시하지 않음(요청 3배 방지)
- 1단 탭 선택 표시: 검색 결과 화면에서는 범위에 해당하는 1단 탭을 선택 상태로

### 범위별 결과 화면
- 공통: 검색어 2~50자, 관련도순(기본)·최신순, 기간(1주/1개월/1년/전체), 페이지당 20건·최대 50페이지, 제목·요약 하이라이트(F-022 방식, HTML 주입 없음)
- 기술 뉴스: 지금 S-04 그대로 (태그·소스 필터)
- 보안 뉴스: 필터는 지역(국내/해외)만, 카드는 보안 뉴스 카드(썸네일 없음)
- 자유 게시판: 필터는 말머리(질문/토론/공유)만, 카드는 자유 게시판 카드(말머리·작성자·해결됨), 누르면 상세. 하이라이트는 제목·excerpt
- 결과 없음: 범위 이름을 넣어 안내 ("자유 게시판에서 찾지 못했어요") + 다른 범위로 검색 링크

### 색인 (dba·server)
- 같은 bigram + FULLTEXT 방식(D-03)으로 보안 뉴스·자유 게시판 글도 색인. 색인 테이블을 나눌지 `post_search`에 종류를 더할지는 dba 판단
- 보안 뉴스: 수집 시점 색인 + 기존 글 백필
- 자유 게시판: 작성·수정 시 갱신, 삭제·숨김 시 검색 결과에서 제외(해제 시 복구). 본문은 앞 N자(예: 2,000자)만 색인해도 됨 — dba·server가 성능 보고 정함
- 기존 기술 뉴스 검색 결과·성능에 영향 없어야 함 (다른 범위 글이 섞이지 않음)
- 새 마이그레이션은 운영 적용 전 사용자 승인

## 수용 기준
- 세 페이지에서 검색창 안내 문구가 페이지에 맞고, 검색 시 해당 범위 결과 화면으로 이동
- 결과 화면 범위 탭 전환 시 같은 검색어로 해당 범위 결과, 주소 `scope` 동기화, 새로고침·공유 동일
- 보안 뉴스·자유 게시판 한글 부분 일치 검색 동작(예: "취약점", "모노레포"), 숨김·삭제 글 미노출, 자유 게시판 글 수정 후 새 내용으로 검색됨
- 기술 뉴스 검색 결과에 보안·자유 게시판 글 0, 기존 p95 유지. 새 범위 p95 300ms 이하
- 360px 가로 넘침 0, 라이트·다크 정상, 기존 테스트·빌드 통과

## 의견

### server (사전 의견, 2026-11-23)
- 결정 수용. 색인 설계 전에 server 쪽 제약·희망 정리 (dba 판단에 참고)
- **기술 검색 보호가 1순위**: 지금 기술 검색은 `post_search`에 블로그 글만 있다는 전제로 **`posts` 조인 없이** 관련도 정렬함(기간·출처·최신순일 때만 조인). 같은 테이블에 다른 종류를 넣으면 기술 검색에 종류 조건이 붙어 매번 조인이 생기고, FULLTEXT 일치 집합도 커짐
  - → **희망: `post_search`는 블로그 전용 그대로(D-20 유지), 보안 뉴스·자유 게시판은 별도 색인 테이블**(범위별 2개든 종류 컬럼을 둔 1개든 dba 판단. 둘 다 블로그보다 훨씬 작음)
- **자유 게시판 숨김·삭제**: 색인 행을 지웠다 되살리기보다 **검색 시 `community_posts.status = 'VISIBLE'` 조인 필터**를 희망. 숨김·해제 경로가 관리자 숨김·신고 자동 숨김·신고 처리·삭제·탈퇴로 여러 곳이라 행 삭제/복구 방식은 누락 위험이 큼. 글 수가 작아 조인 비용 작음
  - 색인 행 갱신은 작성·수정(제목·본문·태그 변경) 트랜잭션 안에서 server가 함
- **자유 게시판 본문**: 마크다운 제거 텍스트(`markdownExcerpt`와 같은 규칙) **앞 2,000자** + 태그 이름·동의어. 원문 최대 20,000자를 bigram으로 다 넣으면 행당 토큰이 너무 커짐. 2,000자 밖 내용은 검색 안 됨(수용 기준 영향 없음)
- **보안 뉴스**: 수집 시점에 제목·요약·출처 이름 색인 (태그 없음). **기존 글 백필은 bigram 토크나이저가 server 코드라 server 스크립트**로 함 (`scripts/`, 미리보기 기본·`--apply`, 운영 실행은 마이그레이션 적용 뒤 사용자 승인 받아 진행)
- **API 형태 (초안, 색인 확정 후 명세)**: 기존 `GET /search`에 `scope=TECH|SECURITY|COMMUNITY` 추가 (생략 = `TECH`, 지금 동작). 응답 `{ items, total, totalCapped, page, size }` 그대로, 카드는 기존 카드(`kind`, 자유 게시판은 `community` 포함)
  - 범위별 필터: `TECH` = `tagIds`·`sourceIds`, `SECURITY` = `region`, `COMMUNITY` = `category`. 범위에 없는 필터는 400
  - 공통: `q` 2~50자, `sort`, `period`, `page`·`size` 그대로. 캐시 키에 범위·필터 포함
  - 자유 게시판 하이라이트 대상은 `title`·`summary`(excerpt) — 화면에서 처리 (F-022)
- client 주소의 `scope=tech|security|community`(소문자)는 화면 주소이고 API는 대문자 enum으로 맞추길 제안 (기존 `region`·`category`와 같음)

### client (검토·API 형태 제안, 2026-11-23)
- 화면 결정 모두 수용. 아래 형태로 mock 먼저 진행함
- API 형태 제안 (기존 `/search`에 범위 추가, server·dba 재량)
  - `GET /search?q&scope=TECH|SECURITY|COMMUNITY&period&sort&page&size` (`scope` 생략 = `TECH`, 지금 동작 그대로)
  - 범위별 필터: `TECH` = `tagIds`·`sourceIds`(지금), `SECURITY` = `region`, `COMMUNITY` = `category`. 다른 범위 필터가 오면 **무시** 제안 (공유 주소에 섞여도 400이 아니게). client는 범위를 바꿀 때 해당 범위 필터만 남김
  - 응답 `SearchPage` 그대로. 카드는 `PostSummary.kind`로 기존 카드(보안 뉴스 카드·자유 게시판 카드)를 그대로 씀 → `community` 정보(말머리·작성자·해결됨)와 `summary`(자유 게시판은 excerpt 200자) 포함 부탁
  - 자유 게시판 캐시: 숨김·삭제·수정이 검색에 바로 반영돼야 하므로 `COMMUNITY`는 1분 캐시 제외 또는 해당 글 변경 시 무효화 부탁. 1분 늦게 반영 허용이면 알려 주면 화면 안내 문구 없이 그대로 감
- 하이라이트: 지금처럼 client가 검색어로 제목·summary 표시. 본문 뒤쪽에서만 걸린 글은 excerpt에 표시할 곳이 없어 하이라이트 없이 나옴 (허용으로 봄. 필요하면 다음에 `snippet` 필드 검토)
- 화면
  - 검색창: 현재 1단 탭에 맞춰 "기술 뉴스 검색…"·"보안 뉴스 검색…"·"자유 게시판 검색…", 제출 시 `/search?q=&scope=tech|security|community` (주소는 소문자, API는 대문자로 바꿔 보냄). 범위가 정해지지 않는 화면은 마지막 범위(`sessionStorage`), 없으면 기술 뉴스
  - 결과 화면: 맨 위 범위 글자 탭 `기술 뉴스 · 보안 뉴스 · 자유 게시판` (q·정렬·기간 유지, 범위 필터·page 초기화), 1단 탭은 범위에 맞춰 선택 표시
  - 왼쪽 필터: 기술 = 지금 그대로, 보안 = 지역, 자유 게시판 = 말머리. 결과 없음 문구에 범위 이름 + 다른 두 범위 링크

### pm (server·client 의견 결정, 2026-11-23)
- 색인: server 희망 수용 — `post_search`는 블로그 전용 유지, 보안·자유 게시판은 별도 색인(구조는 dba 판단). 자유 게시판 숨김·삭제는 색인 행 대신 검색 시 `status = 'VISIBLE'` 조인으로 거름. 본문은 마크다운 제거 앞 2,000자 + 태그
- 보안 뉴스 백필: server 스크립트, 운영 실행은 마이그레이션 적용 후 사용자 승인
- API: `GET /search`에 `scope=TECH|SECURITY|COMMUNITY`(생략 = TECH), 화면 주소는 소문자 — 두 의견 같음, 수용
- **범위에 없는 필터: 400 (server안)**. client가 범위를 바꿀 때 해당 범위 필터만 남겨 보내므로 공유 주소에 섞여도 화면은 깨지지 않음 (client는 API 호출 전 정리)
- **자유 게시판 캐시: `COMMUNITY`는 캐시하지 않음** (숨김·삭제·수정 즉시 반영, 글 수가 작아 부담 작음). 보안 뉴스는 기술과 같은 캐시
- 본문 뒤쪽에서만 걸린 글의 하이라이트 없음 허용, `snippet`은 Next

### server (client 제안 수용, 2026-11-23)
- 형태 일치. 차이 1건은 client 제안대로 감: **다른 범위 필터는 400이 아니라 무시** (server 초안 철회). 범위 자체 값이 틀리면(`scope=foo`)·자기 범위 필터 값이 틀리면 400
- 카드: 기존 카드 로더 그대로라 `kind`·`community`(말머리·작성자·해결됨)·`summary`(excerpt) 포함
- 자유 게시판 캐시: **`COMMUNITY` 범위는 검색 캐시를 쓰지 않음** (글 수가 작아 비용 작음). 숨김·삭제·수정이 바로 반영됨. `TECH`·`SECURITY`는 지금처럼 1분 캐시
- 본문 뒤쪽에서만 걸린 글 하이라이트 없음 허용 동의. `snippet`은 Next
- 명세는 dba 색인 설계 확정 후 `openapi.yaml`에 씀 (형태는 위와 같아 mock 그대로 진행해도 됨)

### server (pm 결정 확인, 2026-11-23)
- 바로 위 server 항목은 pm 결정과 엇갈려 기록됨 → **pm 결정 따름: 범위에 없는 필터는 400** (위 "무시" 철회). client는 API 호출 전에 범위 밖 필터를 정리해 보내기 바람
- 나머지(별도 색인, `VISIBLE` 조인, 본문 앞 2,000자 + 태그, `COMMUNITY` 캐시 없음, 보안 백필 server 스크립트)는 결정과 같음. dba 색인 설계 기다림

### client (mock 구현, 2026-11-23)
- 범위 밖 필터 400(pm 결정·server 정정) 반영: 화면 주소를 읽을 때(`parseSearch`) 범위 밖 필터를 버려서 API에는 해당 범위 필터만 보냄. mock도 범위 밖 필터 400
- 구현
  - 검색창 안내 문구 페이지별(`기술 뉴스 검색…`·`보안 뉴스 검색…`·`자유 게시판 검색…`), 제출 시 `/search?q=&scope=` (tech면 `scope` 생략, 기존 링크 호환). 범위 없는 화면은 마지막 범위(`sessionStorage`), 헤더 검색 아이콘도 같은 범위
  - 결과 화면: 범위 글자 탭(검색어·정렬·기간 유지, 범위 필터·페이지 초기화), 1단 탭 범위에 맞춰 선택. 기술은 지금 화면 그대로, 보안은 지역·기간, 자유 게시판은 말머리·기간 (왼쪽은 프로필 카드)
  - 결과 없음: "<범위>에서 찾지 못했어요" + 다른 두 범위 검색 링크
- 검증: 테스트 220건(038 6건 신규)·빌드 통과, 로컬 mock 1440 라이트·360 다크·결과 없음 화면 넘침 0
- 배포 보류: 지금 운영 서버는 `scope`를 모르므로 server 배포 후 `build:web` 배포·실서버 대조함. 명세가 위 형태와 다르면 알려 주면 맞춤

### dba (1차) — 색인 설계 `0017` (pm 결정·server 희망 반영)
- **범위별 별도 색인 테이블 2개**: `security_news_search`, `community_search` (구조는 `post_search`와 같음: `title_tokens`·`body_tokens` TEXT, FULLTEXT 제목·전체 2개). `post_search`는 블로그 전용 그대로 → 기술 검색 쿼리·성능 변화 없음
  - 종류 컬럼 1개 테이블 대신 2개로 나눈 이유: 범위마다 크기·증가 속도가 달라 FULLTEXT 일치 집합을 섞지 않음, 자유 게시판은 FK를 `community_posts`에 걸어 다른 종류가 들어갈 수 없게 함
- 자유 게시판: 숨김은 행 유지 + `JOIN community_posts cp ... AND cp.status = 'VISIBLE'` (pm 결정). **단 삭제(`DELETED`)·탈퇴는 색인 행 삭제 필요** — 본문 토큰도 작성 내용이라 탈퇴 후 남기면 안 됨 (soft delete UPDATE와 같은 트랜잭션에서 `DELETE FROM community_search WHERE post_id = ?`). `community.sql` 삭제 절차에 반영, 정합성 검사 `deleted_post_still_indexed` 추가
- 보안 뉴스: 지역 필터는 `posts FORCE INDEX (idx_posts_search_filter)` 조인으로 `source_id IN (...)` (기술 검색과 같은 방식). 정합성 검사 `news_index_wrong_kind` 추가

### server (운영 승인 확인, 2026-11-23)
- 승인 확인. 운영 `devfeed`에는 아직 `security_news_search`·`community_search` 없음 (현재 `post_search`만) → dba 0017 적용 알림 기다림
