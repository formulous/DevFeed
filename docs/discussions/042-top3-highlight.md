# 042. 목록 상단 "이번 주 인기" TOP 3

- 상태: open
- 제기: pm (사용자 요청)
- 관련: server, client, dba
- 관련 문서: `docs/spec/03-screens.md` S-01·S-14·S-16, `docs/discussions/035`(댓글순·좋아요순)

## 배경
- 사용자 요청 (2026-11-24): 좋아요·댓글 수 기준으로 목록 상단에 TOP 3~5 인기글을 알아보기 쉽게 표시
- 사용자 결정: **세 탭 모두**(자유 게시판·기술 뉴스·보안 뉴스), 모양은 **순위 배지 카드 줄**

## 결정 (pm)
### 기준 (server)
- 대상: 최근 7일 발행 글, 점수 = **좋아요 수 + 댓글 수**, 점수 1 이상, 상위 **3건**. 동점은 댓글 수 → 최신 발행순. 최대 10분 지연(캐시) 허용
- 범위: 자유 게시판 `VISIBLE`만, 기술 뉴스 블로그 글만, 보안 뉴스 보안 글만 (서로 섞이지 않음)
- 현재 필터 반영: 기술 뉴스 분야(`field`), 자유 게시판 말머리(`category`), 보안 뉴스 지역(`region`). 태그·소스 필터는 반영하지 않음(상위 3건이 거의 비게 됨)
- 3건 미만이면 있는 만큼, 0건이면 영역 자체를 숨김 (보안 뉴스는 반응이 적어 자주 숨겨질 수 있음 — 허용)
- API 형태(기존 인기 경로에 `sort=REACTIONS&size=3` 또는 새 경로)는 server 재량. dba는 쿼리가 기존 인덱스로 충분한지 확인 (035와 같은 형태라 마이그레이션 없을 것으로 예상)

### 화면 (client)
```
🔥 이번 주 인기                                   더 보기 ›
┌──────────────┬──────────────┬──────────────┐
│ ①            │ 2            │ 3            │   ← 1위 번호는 강조색, 2·3위 기본색
│ 모노레포 vs   │ MSA로 쪼갰다가 │ AI 코드 리뷰, │   ← 제목 2줄 말줄임
│ 멀티레포…     │ 다시 합치신…   │ 팀에서 실제…  │
│ 말머리/출처   │               │              │
│ ♡ 19  💬 30   │ ♡ 16  💬 24   │ ♡ 14  💬 18   │
└──────────────┴──────────────┴──────────────┘
(최신 목록)
```
- 위치: 각 탭 **최신순 목록 맨 위**(정렬 글자 탭 아래, 첫 글 위). 인기·댓글·좋아요·추천순 화면에는 넣지 않음(이미 순위 목록)
- 데스크톱: 3칸 가로 카드, 연한 배경(`subtle`)으로 목록과 구분, 큰 순위 숫자. 1위만 강조색
- 모바일: 세로 3줄 압축형(순위 숫자 + 제목 1줄 + ♡·💬), 같은 배경 박스
- 카드 클릭: 자유 게시판은 상세, 기술·보안 뉴스는 지금 목록과 같이 원문 새 탭 + 조회 기록
- 머리말 `🔥` 대신 아이콘 컴포넌트(불꽃 또는 트렌드)를 써도 됨. "더 보기 ›": 자유 게시판 → 좋아요순 7일, 기술 뉴스 → 댓글순 7일, 보안 뉴스 → 인기순 7일
- 같은 글이 아래 최신 목록에도 나오는 것은 허용 (중복 제거 안 함)
- 로딩 중엔 3칸 스켈레톤, 실패하면 영역 숨김(목록은 그대로)

## 수용 기준
- 세 탭 최신순에서 TOP 영역 표시, 점수 순서·필터 반영, 0건이면 숨김, 범위 간 섞임 0
- 1440 3칸·360 세로, 라이트·다크 정상, 가로 넘침 0, 목록 첫 화면 로딩 지연 체감 없음(API p95 300ms 이하)
- 테스트·빌드 통과

## 의견

### dba (1차) — TOP 3 쿼리 인덱스 검토: 마이그레이션 없음
- 쿼리 형태: 035와 같은 기간 범위 스캔 + 카운터 정렬. 점수식은 `posts.like_count + posts.comment_count`(026 비정규화 카운터), 정렬 `점수 DESC, comment_count DESC, published_at DESC, id DESC LIMIT 3`
  - 기술: `kind = 'BLOG'` + 7일 → `idx_posts_kind_published`, 분야는 `EXISTS (post_tags PK)`
  - 보안: `kind = 'SECURITY_NEWS'` + 7일, 지역은 `source_id IN (...)` → `idx_posts_source_published`
  - 자유 게시판: `community_posts (status[, category], published_at)` 범위 → `posts` PK 조인
- 측정 (`devfeed_perf` 블로그 10만·보안 4만·커뮤니티 2만, DB p95)
  | 쿼리 | p95 | 읽은 행 |
  |---|---|---|
  | 기술 / + 분야 | 0.54 / 0.60ms | 643 / 685 |
  | 보안 / + 국내 | 0.23 / 0.14ms | 217 / 110 |
  | 자유 / + 말머리 | 0.22 / 0.09ms | 690 / 230 |
  - 7일 고정이라 읽는 행이 기간 안 글 수로 제한됨 → 새 인덱스 불필요, 운영 적용 절차 없음
- 점수식에 인덱스를 둘 수 없어(합산 정렬) 기간을 늘리면 비례해 늘어남 (035와 같은 주의). 10분 캐시 전제

### server (명세·구현, 2026-11-24)
- API: 새 경로 없이 **기존 인기 경로 세 개에 `sort=REACTIONS` + `size`** 추가. TOP 3 호출은 각 탭에서
  - 기술: `GET /posts/popular?period=WEEK&sort=REACTIONS&size=3[&field=]`
  - 보안: `GET /security-news/popular?period=WEEK&sort=REACTIONS&size=3[&region=]` (보안 인기에 `sort=VIEWS|REACTIONS`가 새로 생김, 기본 `VIEWS`)
  - 자유 게시판: `GET /community/popular?period=WEEK&sort=REACTIONS&size=3[&category=]`
- 기준은 pm 결정 그대로: 7일, 좋아요 + 댓글 합 1 이상, 합 → 댓글 수 → 최신 발행순, 범위 분리, 태그·소스 필터 없음. 0건이면 `items: []`
- `size`는 1~20(기본 20, 범위 밖 400). 10분 캐시된 상위 20건의 앞부분만 잘라 주므로 TOP 3와 "더 보기" 목록 순서가 같음
- 카드는 지금 인기 응답(`PopularPost`)과 같음 → `likeCount`·`commentCount` 들어 있음
- 명세 `openapi.yaml` 갱신(lint 기준선 그대로). dba 인덱스 검토(마이그레이션 없음) 확인
- 검증: unit 176, e2e 90 통과 (042 2건 신규: 합·동점 순서, 분야·지역·말머리 필터, 범위 섞임 없음, `size` 앞부분, 400). perf API 첫 요청(캐시 없음) 8ms 이하, 캐시 후 1~5ms
- 배포: 스키마 변경 없고 기존 호출과 호환이라 커밋 후 바로 배포함. client는 배포 알림 받으면 실서버 대조
- **운영 배포 완료** (health OK). 운영 확인: 기술 3건(합 4·3·3), 보안 1건(1+1), 자유 게시판 3건(20+30·16+24·15+18), `size=21` 400. 응답 시간은 공인 경로 기준 0.3초 안쪽(네트워크 포함)

### pm (server 배포 확인, 2026-11-24)
- 공개 API `sort=REACTIONS&size=3`: 자유 게시판 50·40·33점, 말머리 질문 15·11(댓글 6)·11(댓글 5) → 동점 댓글 수 우선 확인, 기술 뉴스 블로그만 3건, 보안 뉴스 1건(있는 만큼)
- 남은 것: client 배포 → pm 공개 확인

### client (1차) — API 형태 제안·mock 구현
- **API 제안 (server 재량, 바꾸면 client가 맞춤)**: 새 경로 없이 기존 인기 경로 3개에 `sort=REACTIONS`와 `size`를 더함
  - `GET /posts/popular?period=WEEK&sort=REACTIONS&size=3[&field=]`
  - `GET /security-news/popular?period=WEEK&sort=REACTIONS&size=3[&region=]` (지금 `sort`가 없어 `VIEWS|REACTIONS` 추가)
  - `GET /community/popular?period=WEEK&sort=REACTIONS&size=3[&category=]`
  - `REACTIONS`: 점수 = `likeCount + commentCount` 1 이상, 점수 → 댓글 수 → 최신 발행순 (pm 기준 그대로). `size` 1~20, 기본 20 (생략하면 지금과 같음). 응답은 지금 `PopularPost` 그대로(카드에 `likeCount`·`commentCount` 필요)
  - 캐시: 기간 × 필터 × 정렬 10분, `size`는 캐시 키에서 빼고 20건 캐시에서 잘라도 됨
- client mock 구현 (커밋만, server 배포 전이라 `build:web` 배포 안 함)
  - `WeeklyTop`: 기술 뉴스(`/tech`)·보안 뉴스(`/security`)·자유 게시판(`/community`) 최신순 목록 맨 위. 정렬·인기 화면에는 없음
  - md(768px) 이상 3칸 카드: 큰 순위 숫자(1위 강조색), 제목 2줄, 말머리/출처, ♡·💬. 미만 세로 3줄: 순위·제목 1줄·♡·💬. `subtle` 배경 박스, 머리말은 트렌드 아이콘 + "이번 주 인기"
  - 로딩 3칸 스켈레톤, 0건·실패면 숨김(목록 그대로, 재시도 없음). 클릭: 자유 게시판 상세 / 뉴스 원문 새 탭 + 조회 기록
