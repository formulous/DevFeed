# 029. 좌측 프로필 카드와 활동 등급

- 상태: open
- 제기: pm (사용자 요청)
- 관련: dba, server, client
- 관련 문서: `docs/spec/02-features.md` F-082·F-083, `docs/spec/03-screens.md` 공통 레이아웃, `docs/spec/04-roadmap.md` M10, `docs/discussions/026`

## 배경
- 사용자 요청 (2026-11-22): 각 탭 좌측 상단에 네이버 블로그 프로필 영역처럼 유저 정보(닉네임, 등급, 활동 수치)를 보여 줌
- 사용자 결정
  - 수치: **좋아요 수, 댓글 수, 읽은 글 수, 북마크 수** (회원이 글을 쓰지 않는 서비스라 "게시글 수" 대신)
  - 등급: **활동 점수 기반**, 등급 이름은 **개발자·보안 관련 이름**
  - 게스트: 같은 자리에 **로그인 안내 카드**
  - 프로필 이미지: **자동 아바타** (업로드 없음)
- 포트폴리오 어필: 점수 원장(ledger) 설계로 어뷰징 방지·회수 처리, 카운터 정합성, 등급 계산 캐시

## 결정 (pm)

### 화면: 프로필 카드 (F-082)
```
┌ 좌측 열 맨 위 ─────────────┐
│ (Y)  yeonchan               │  ← 자동 아바타 + 닉네임
│      Lv.3 Senior            │  ← 등급 배지
│ ████████░░░░  1,240 / 2,000P│  ← 다음 등급까지 진행 막대
│ 다음 등급까지 760P   등급 안내 │
│ ─────────────────────────── │
│ 좋아요 12    댓글 5           │
│ 읽은 글 230  북마크 18  ›     │  ← 읽은 글·북마크는 해당 화면 링크
└─────────────────────────────┘
[ 기존 필터 / 출처 사이드바 ]
```
- 위치: 최신·추천·인기·보안 뉴스 4개 탭과 검색 화면의 **좌측 열 맨 위**, 기존 필터·출처 사이드바 위. 좌측 열이 없는 화면(인기 등)은 같은 폭의 좌측 열을 만들어 카드만 둠
- 022 디자인 유지: 상자 대신 여백·1px 선, 무채색. 좌측 열 폭 그대로, 사이드바 스크롤 없는 원칙(017) 유지 → 카드 높이 약 180px 이내
- 숫자는 1,000 이상 `1.2k`. 읽은 글 → S-09, 북마크 → S-08 링크. 좋아요·댓글은 숫자만 (목록 화면은 Next)
- 닉네임 클릭 → S-10 설정
- 1440px 이상 좌우 광고(025)와 겹치지 않음 (광고는 바깥, 카드는 좌측 열 안)
- `lg` 미만(모바일): 카드 숨김. 헤더 프로필 메뉴(▾) 맨 위에 아바타·닉네임·등급 한 줄 표시

### 게스트 카드
```
┌──────────────────────────────┐
│ DevFeed에 로그인하고            │
│ 좋아요·댓글로 등급을 올려 보세요   │
│ [로그인]  [회원가입]             │
└──────────────────────────────┘
```

### 자동 아바타
- 원 안에 닉네임 첫 글자(영문은 대문자). 배경은 닉네임에서 정해지는 무채색 계열 5~6단계 중 하나, 라이트·다크 모두 대비 4.5:1 이상
- 댓글 작성자 옆에도 같은 아바타(작게) + 등급 배지 표시 (026 댓글 영역)

### 활동 등급 (F-083)
| 레벨 | 이름 | 누적 점수 |
|---|---|---|
| Lv.1 | Hello World | 0 |
| Lv.2 | Junior Dev | 100 |
| Lv.3 | Senior Dev | 500 |
| Lv.4 | Tech Lead | 2,000 |
| Lv.5 | Architect | 5,000 |
- 이름은 023 원칙대로 영어 표기. 보안 계열 대안(Script Kiddie → Bug Hunter → Pentester → Red Teamer → White Hat)은 사용자 선택 시 교체 (이름만 바뀌므로 구현 영향 없음)

### 점수 규칙
| 활동 | 점수 | 제한·회수 |
|---|---|---|
| 글 읽기 (원문 이동, F-012) | +1 | 같은 글은 처음 1회만, 하루 최대 30점 |
| 좋아요 | +2 | 같은 글 1회만. 취소하면 회수 |
| 댓글·답글 작성 | +5 | 하루 최대 10개분(50점). 본인 삭제·관리자 숨김 시 회수, 숨김 해제 시 복구 |
| 북마크 | 0 | 수치만 표시, 점수 없음 (저장만 반복하는 어뷰징 방지) |
- 점수는 **누적 원장** 기준: 읽은 기록을 지우거나 1년 보관 만료로 기록이 사라져도 읽기 점수는 남음. 좋아요 취소·댓글 삭제처럼 활동 자체를 되돌린 경우만 회수
- 회수로 점수가 내려가면 등급도 내려감 (최저 Lv.1, 점수 음수 없음)
- 기존 회원: 도입 시 현재 읽은 기록·좋아요·보이는 댓글로 초기 점수 계산 (하루 제한은 초기 계산에 적용 안 함)
- "등급 안내" 클릭 → 작은 모달로 위 두 표 표시 (해요체)
- 탈퇴(F-032): 점수·원장 삭제

### 수치 기준
- 좋아요 = 지금 좋아요 중인 글 수, 댓글 = 보이는 댓글+답글 수(삭제·숨김 제외), 읽은 글 = 읽은 기록 현재 개수, 북마크 = 북마크 현재 개수
- 본인 화면은 활동 직후 바로 반영(낙관적 갱신 또는 재조회), 최대 지연 없음

## 수용 기준
- 회원: 4개 탭·검색 좌측 맨 위에 카드, 수치가 실제 행 수와 일치, 활동 직후 반영
- 게스트: 같은 자리에 로그인 안내 카드
- 점수: 같은 글 재읽기 0점, 하루 31번째 읽기 0점, 좋아요 취소·댓글 삭제·숨김 시 회수, 숨김 해제 복구, 읽은 기록 삭제 시 점수 유지
- 경계값(99→100, 499→500 …)에서 등급·진행 막대 정확
- 1280×720에서 카드+필터 사이드바가 스크롤 없이 들어옴(017 기준 유지), 360px 헤더 메뉴 표시, 라이트·다크
- 피드 API p95 300ms 이하 유지 (카드는 별도 요청 1회)
- 탈퇴 후 점수·원장 잔존 0

## 후속 작업
- dba - 점수 원장·회원 누적 점수(카운터) 스키마, 하루 제한 계산 인덱스, 초기 점수 백필 쿼리, 탈퇴 대상 추가
- server - `GET /me/profile`(닉네임·등급·점수·다음 등급 기준·수치 4개), 활동 API(조회·좋아요·댓글·숨김)에 점수 적립·회수, 댓글 응답 작성자에 `grade` 추가, 명세 → 구현·e2e
- client - 프로필 카드·게스트 카드·자동 아바타·등급 안내 모달·댓글 작성자 배지, mock 선행, 공개 배포는 server 배포 후
- pm - `02-features.md` F-082·F-083, `03-screens.md` 공통 레이아웃, `04-roadmap.md` M10 (완료)
- 운영 DB 마이그레이션은 사용자 확인 후 적용
